# agent-skills

Скилл планирования для команды, которая пишет код с агентами: общий план лежит в репозитории
проекта, поэтому работу можно передать коллеге и подхватить за ним.

## Что внутри

| Путь | Что это |
|---|---|
| `skills/team-task-workflow` | процесс планирования: фича → задачи, план в `docs/plans/<логин>/` |
| `install.sh` | раскладывает скилл симлинками по папкам агентов |

## Как это работает

- **План — это файлы.** Каждый разработчик планирует в своей папке `docs/plans/<логин>/`. Фича
  режется на задачи, большая работа — на этап из нескольких фич.
- **Один чат — один кусок.** Уровень планируется в отдельном чате: сначала вопросы разработчику,
  потом разбивка. Каждая задача делается в свежем чате из вставленного файла задачи.
- **План едет вместе с кодом.** Файлы плана коммитятся в ветку фичи, статус, отклонения и долг
  записываются туда же. Коллега берёт ветку и продолжает с того же места.
- **Правила веток — ваши.** При первом запуске скилл выясняет, как в проекте называют ветки,
  сливают PR и оформляют коммиты, и записывает это в `docs/plans/README.md`.
- **Закрытая фича оставляет итог.** Файлы задач удаляются после закрытия, в `STATUS.md` остаётся
  сводка и ссылка на коммит, из которого их можно вернуть.

## Установка

```bash
git clone https://github.com/Meerzus/agent-skills.git
```

```bash
./agent-skills/install.sh
```

Скрипт ставит скилл Claude и Codex, если их папки уже есть на машине (`~/.claude`, `~/.codex`).
Агента, который ещё ни разу не запускался, назовите явно: `--claude`, `--codex`. Общая папка
`~/.agents/skills` ставится только по флагу `--agents`: агент, который читает и её, и свою папку,
показал бы скилл дважды.

Посмотреть, что будет сделано, ничего не меняя: `./install.sh --dry-run`.

Скрипт ничего не удаляет. Если на месте скилла уже что-то лежит:

- совпадает с репозиторием или это битая ссылка — заменяется ссылкой, старое уходит в
  `~/.agent-skills-backup/<время>/`;
- отличается — пропускается с пометкой `SKIPPED`, скрипт завершается с кодом 2. Сравните вручную и
  повторите с `--force` (старое тоже уйдёт в бэкап).

Нужны bash и симлинки: macOS, Linux, WSL.

## Начать

В чате с агентом, в репозитории проекта: «подключи процесс к проекту», затем «распланируй фичу» и
описать задачу. Дальше каждый чат сам называет файл, который нужно вставить в следующий.

Чат не должен убегать вперёд. После «распланируй фичу» он пишет бриф и останавливается. Чат с
брифом сначала задаёт вопросы, ждёт ответов, показывает итог и только после «да» пишет задачи.
Если агент написал всё сразу — он пропустил остановки; скажите ему об этом и начните чат заново.

Передать работу: «передаю фичу». Продолжить за коллегой: «подхвати за …».

## Модели

Скилл не привязан к моделям одного вендора. В файлах плана указан уровень модели — сильная, средняя
или малая, — а какая модель вашей команды ему соответствует, записано в `docs/plans/README.md`
проекта. При подключении чат спросит, какие модели у вас есть и какая к какому уровню относится.
Поменять позже: «обнови модели».

| Уровень | Для чего | Пример: Claude, ноябрь 2026 |
|---|---|---|
| Сильная | план этапа | Fable 5.2 |
| Средняя | план фичи, обычные и сложные задачи, проверка | Opus 5.5 |
| Малая | механические задачи | Sonnet 5.5 |

## Обновление

Установлена ссылка, а не копия, поэтому достаточно `git pull` в папке репозитория.

## Агенты без поддержки скиллов

Файлы плана задуманы как полное первое сообщение, поэтому процесс работает и там. В файл глобальных
правил такого агента добавьте строку, подставив путь к склонированному репозиторию:

> Если сообщение начинается с шапки, называющей скилл `team-task-workflow`, сначала прочитай
> `<путь к agent-skills>/skills/team-task-workflow/SKILL.md` и следуй ему.

## Что зависит от агента

- «Усилие» в шапках файлов — настройка, которая есть не у всех агентов. Если у вашего её нет,
  скажите об этом при подключении, и скилл не будет её писать.
- `references/planning.md` упоминает субагента; агент без субагентов делает этот поиск сам.
